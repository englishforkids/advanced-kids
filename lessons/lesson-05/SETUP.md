# Налаштування з нуля — крок за кроком

Ця інструкція проведе від порожнього місця до працюючого уроку з живими відповідями учнів.
Нічого знати наперед не треба: жодного терміналу, жодного програмування — усе через сайт.

**Загальний час:** ~20 хвилин. **Вартість:** 0 грн, обидва сервіси безкоштовні.

Що вийде в результаті:

- урок лежить в інтернеті за постійним посиланням;
- ви відкриваєте його на своєму ноуті й ведете заняття;
- учні заходять за окремим посиланням з телефонів і відповідають на ваші запитання.

# ЧАСТИНА 1 · GitHub — щоб урок жив в інтернеті

## Крок 1.1 — Створити акаунт

1. Відкрийте **https://github.com/signup**
2. **Email** — введіть свою пошту → `Continue`
3. **Password** — придумайте пароль (мінімум 15 символів або 8 символів з цифрою й літерою) → `Continue`
4. **Username** — це стане частиною адреси вашого сайту.
   Наприклад `taras-english` → сайт буде `https://taras-english.github.io/…`
   Тільки латиниця, цифри й дефіси. → `Continue`
5. На питання про розсилку введіть `n` → `Continue`
6. Пройдіть візуальну перевірку → `Create account`
7. На пошту прийде **8-значний код** → введіть його

Готово, ви в GitHub.

> Пізніше GitHub попросить увімкнути двофакторну автентифікацію. Не ігноруйте —
> без неї через 45 днів акаунт обмежать. Найпростіше: **Settings → Password and authentication
> → Two-factor authentication → Enable** і відсканувати QR-код застосунком Google Authenticator.

## Крок 1.2 — Створити репозиторій

Репозиторій — це просто папка з файлами вашого сайту.

1. Праворуч угорі натисніть **`+`** → **New repository**
2. **Repository name:** `lesson5-inversion`
   (можна будь-яку назву латиницею — вона буде в адресі сайту)
3. **Description:** необов'язково, наприклад `Interactive English lesson`
4. Оберіть **Public**
   ⚠️ Це обов'язково: безкоштовний GitHub Pages працює лише з публічними репозиторіями.
   Учні все одно мають бачити сторінку, тож нічого приватного там немає.
5. **Не ставте** галочку `Add a README file` — ми завантажимо свій
6. **Create repository**

## Крок 1.3 — Завантажити файли уроку

1. Розпакуйте на комп'ютері архів `lesson5-site.zip`.
   Усередині має бути: `index.html`, папка `img`, папка `sql`, папка `docs`,
   файли `README.md`, `SETUP.md`, `.nojekyll`
2. На сторінці порожнього репозиторію натисніть посилання **uploading an existing file**
   (або кнопка **Add file → Upload files**)
3. **Виділіть увесь вміст розпакованої папки** — саме вміст, а не саму папку —
   і перетягніть у вікно браузера.
   Папки `img`, `sql`, `docs` перетягуються цілком, GitHub їх прийме.
4. Дочекайтесь, поки всі файли з'являться в списку (близько 27 файлів)
5. Унизу в полі **Commit changes** напишіть `Перший завантаж`
6. Натисніть зелену **Commit changes**

> Файл `.nojekyll` може не показатися у списку — Windows і macOS ховають файли,
> що починаються з крапки. Якщо його не видно: натисніть **Add file → Create new file**,
> у полі назви напишіть `.nojekyll`, залиште вміст порожнім і збережіть.

## Крок 1.4 — Увімкнути сайт

1. У репозиторії вгорі відкрийте вкладку **Settings** (значок шестерні)
2. У лівому меню знайдіть **Pages** (розділ *Code and automation*)
3. **Build and deployment → Source:** оберіть **Deploy from a branch**
4. **Branch:** оберіть `main`, папку залиште **`/ (root)`** → **Save**
5. Зачекайте 1–2 хвилини й оновіть сторінку. Угорі з'явиться зелена смуга:
   *Your site is live at …*

Ваша адреса:

```
https://ВАШ-USERNAME.github.io/lesson5-inversion/
```

Відкрийте її. Має з'явитися нічна школа й напис **LESSON 5**.
**Збережіть це посилання в закладки** — це і є ваш урок.

Якщо бачите помилку 404 — зачекайте ще хвилину й оновіть сторінку через **Ctrl+Shift+R**.

# ЧАСТИНА 2 · Supabase — щоб працювали телефони учнів

Урок уже працює. Але без цієї частини кнопки на телефонах учнів не з'являться:
сторінка не матиме куди передавати їхні відповіді.

## Крок 2.1 — Створити акаунт

1. Відкрийте **https://supabase.com/dashboard**
2. Натисніть **Sign in with GitHub** — це найшвидше, окремий пароль не потрібен
3. GitHub спитає дозвіл → **Authorize supabase**

## Крок 2.2 — Створити проєкт

1. **New project** (якщо просить створити організацію: назва `English lessons`,
   тип `Personal`, план `Free` → `Create organization`)
2. **Project name:** `english-lessons`
3. **Database Password:** натисніть **Generate a password** і **збережіть його**
   у нотатках. Для нашого уроку він не знадобиться, але відновити його не можна.
4. **Region:** оберіть найближчий — `Central EU (Frankfurt)`
5. **Create new project**
6. Зачекайте 1–2 хвилини, поки проєкт розгортається

## Крок 2.3 — Скопіювати дві речі

Обидва значення публічні — їх можна спокійно тримати у файлі сайту.

**Project URL:**

1. Ліве меню внизу → **Settings** (шестерня)
2. **Data API**
3. Угорі поле **Project URL** — скопіюйте. Виглядає так:
   `https://abcdefghijklm.supabase.co`

**Ключ:**

1. Там же в **Settings** → **API Keys**
2. Вкладка **Publishable key** → натисніть значок копіювання
3. Ключ виглядає так: `sb_publishable_AbCdEf123…`

> Якщо у вашому проєкті замість цього є старий **anon** ключ
> (довгий рядок, що починається з `eyJ…`) — він теж підходить, беріть його.
> Обидва ключі призначені для публічного використання у коді сторінки:
> вони не дають доступу до даних без окремого дозволу.

## Крок 2.4 — Перевірити налаштування Realtime

1. Ліве меню → **Realtime** → **Settings**
2. Переконайтеся, що **Allow public access** увімкнено (це значення за замовчуванням)

Якщо цей перемикач вимкнути, телефони учнів не зможуть підключитися до кімнати.

# ЧАСТИНА 3 · З'єднати одне з одним

Тепер вставимо два скопійовані значення у файл уроку. Робимо це прямо на сайті GitHub,
нічого качати не треба.

## Крок 3.1 — Відкрити файл для редагування

1. Поверніться у свій репозиторій на GitHub
2. Натисніть на файл **`index.html`**
3. Угорі праворуч натисніть **олівець** (`Edit this file`)

## Крок 3.2 — Знайти блок налаштувань

Натисніть **Ctrl+F** (пошук у файлі) і введіть `LESSON_CONFIG`.
Це приблизно 15-й рядок файлу. Виглядає так:

```js
window.LESSON_CONFIG = {
  // Settings → Data API → Project URL
  SUPABASE_URL  : 'https://ВАШ-ПРОЄКТ.supabase.co',
  // Settings → API Keys → publishable key (sb_publishable_…). Старий anon теж підходить.
  SUPABASE_KEY  : '',
  // true → відповіді пишуться в таблицю (спершу виконайте sql/schema.sql)
  SAVE_ANSWERS  : false
};
```

## Крок 3.3 — Вставити свої значення

Замініть два рядки. Має вийти щось таке (з **вашими** значеннями):

```js
window.LESSON_CONFIG = {
  SUPABASE_URL  : 'https://abcdefghijklm.supabase.co',
  SUPABASE_KEY  : 'sb_publishable_AbCdEf123456789',
  SAVE_ANSWERS  : false
};
```

На що звернути увагу:

- значення **всередині лапок**, лапки не видаляти;
- **без пробілів** на початку і в кінці ключа;
- у кінці рядка залишається **кома**;
- адреса **без слеша** в кінці.

## Крок 3.4 — Зберегти

1. Угорі праворуч зелена кнопка **Commit changes…**
2. У віконці напишіть `Підключив Supabase` → **Commit changes**
3. Зачекайте хвилину — GitHub перезбирає сайт

## Крок 3.5 — Перевірити

1. Відкрийте свій урок і натисніть **Ctrl+Shift+R** (щоб браузер не показав стару версію)
2. Угорі натисніть **📡 Connect**
3. Натисніть **Start live room**
4. Статус має стати **live · Supabase** ✅

Якщо написано **local only (same browser)** — ключ або адреса вставлені неправильно.
Дивіться розділ «Типові помилки» наприкінці.

# ЧАСТИНА 4 · Перевірка з телефоном

1. На ноуті: **📡 Connect → Start live room → Copy** (посилання скопійовано)
2. Надішліть це посилання собі в месенджер і відкрийте **на телефоні**
   (або просто відскануйте QR-код у тому ж вікні камерою)
3. На телефоні введіть ім'я → **Join**
4. На ноуті в панелі Connect має з'явитися **Connected: 1**
5. На ноуті перейдіть на розділ **Chapter 1** (стрілкою →)
6. Унизу праворуч у панелі керування натисніть **Open on devices**
7. На телефоні миттєво з'являється питання з чотирма варіантами. Натисніть один.
8. На ноуті бачите свій голос. Натисніть **Show results** — на телефоні з'являться відсотки.

Якщо це спрацювало — усе готово до уроку.

# ЧАСТИНА 5 · Опційно: зберігати відповіді в базі

Це **не обов'язково**. Без цього кроку урок повністю працює, просто відповіді живуть
тільки поки відкрита вкладка (і їх завжди можна вивантажити кнопкою
**Export answers (CSV)**).

Вмикайте, якщо хочете архів відповідей після кожного заняття.

## Крок 5.1 — Створити таблицю

1. У Supabase ліве меню → **SQL Editor**
2. **New query**
3. Відкрийте файл `sql/schema.sql` з вашого репозиторію, скопіюйте **весь** вміст
4. Вставте у вікно запиту
5. Натисніть **Run** (або Ctrl+Enter)
6. Внизу має з'явитися **Success. No rows returned**

## Крок 5.2 — Увімкнути запис

1. GitHub → `index.html` → олівець
2. Знайдіть `SAVE_ANSWERS` і змініть `false` на `true`:

```js
  SAVE_ANSWERS  : true
```

3. **Commit changes**

## Крок 5.3 — Перевірити

Проведіть тестове голосування з телефона, потім у Supabase:
**Table Editor → lesson_answers** — там має з'явитися рядок з вашою відповіддю.

Подивитися відповіді однієї кімнати можна в **SQL Editor**:

```sql
select created_at, chapter, task, student_name, value
from lesson_answers
where room = '4821'
order by created_at;
```

(замініть `4821` на код своєї кімнати)

# ЧАСТИНА 6 · Щоразу перед уроком

Коротка рутина, 2 хвилини:

1. Відкрийте урок за своїм посиланням
2. **📡 Connect → Start live room** → статус **live · Supabase**
3. **Copy** → киньте посилання в чат Zoom (або покажіть QR на екрані)
4. Дочекайтесь, поки лічильник **Connected** дорівнюватиме кількості учнів
5. Ведіть урок. Учнівські кнопки відкриваються в панелі внизу праворуч: **Open on devices**

> ⚠️ **Важливо про безкоштовний Supabase:** якщо проєктом не користуватися
> **сім днів поспіль**, він засинає. Дані залишаються, але кімната не працюватиме.
> Розбудити: зайти на **https://supabase.com/dashboard**, відкрити проєкт і натиснути
> **Restore project** — займає 1–2 хвилини.
>
> Тому якщо між уроками буває пауза більше тижня — перевірте кімнату **за день до заняття**,
> а не за п'ять хвилин до початку. Щотижневі уроки тримають проєкт активним самі собою.

# ЧАСТИНА 7 · Типові помилки

| Що бачите | Що робити |
|---|---|
| **404** замість уроку | Зачекайте 2 хвилини після увімкнення Pages. Перевірте, що `index.html` лежить у корені репозиторію, а не всередині вкладеної папки |
| Сторінка є, але **картинки не завантажились** | Папка `img` не завантажилась або завантажилась із іншим іменем. Має бути саме `img` маленькими літерами, поруч з `index.html` |
| **local only (same browser)** | Ключ або адреса не вставлені. Перевірте: адреса починається з `https://` і закінчується на `.supabase.co` без слеша; ключ у лапках; після Commit минула хвилина; ви оновили сторінку через Ctrl+Shift+R |
| Статус **unavailable** | Немає інтернету або проєкт Supabase заснув — розбудіть його в панелі (див. Частину 6) |
| Учень відкрив лінк, але бачить **«Could not join»** | Перевірте, що ви натиснули **Start live room**, і що в Supabase **Realtime → Settings → Allow public access** увімкнено |
| Учні бачать урок, але **не бачать питання** | Питання з'являються лише після **Open on devices** у панелі внизу праворуч. У розділах без активності телефон завжди показує «listen and watch» |
| Змінив файл, а на сайті **старе** | GitHub Pages оновлюється до хвилини. Далі — **Ctrl+Shift+R**. На телефоні: закрити вкладку й відкрити посилання заново |
| Учень зайшов **посеред уроку** і нічого не бачить | Нічого робити не треба: телефон сам перепитує стан кожні 20 секунд |

# ЧАСТИНА 8 · Шпаргалка: що куди вставляти

| Значення | Де взяти | Куди вставити |
|---|---|---|
| Project URL | Supabase → Settings → Data API → Project URL | `index.html` → `SUPABASE_URL` |
| Ключ | Supabase → Settings → API Keys → Publishable key | `index.html` → `SUPABASE_KEY` |
| SQL для таблиці | файл `sql/schema.sql` у репозиторії | Supabase → SQL Editor → Run |
| Посилання на урок | GitHub → Settings → Pages | у закладки, для себе |
| Посилання для учнів | сам урок → 📡 Connect → Copy | чат Zoom |

Підсумковий вигляд блоку налаштувань у `index.html`:

```js
window.LESSON_CONFIG = {
  SUPABASE_URL  : 'https://ваш-ідентифікатор.supabase.co',
  SUPABASE_KEY  : 'sb_publishable_ваш_ключ',
  SAVE_ANSWERS  : false
};
```

## Наступні уроки

Коли робитимете Lesson 6, не створюйте нічого заново. Просто покладіть новий файл
у той самий репозиторій, наприклад `lesson6.html`, і він буде доступний за адресою
`https://ВАШ-USERNAME.github.io/lesson5-inversion/lesson6.html`.
Той самий проєкт Supabase обслуговуватиме всі уроки — кімнати не конфліктують,
бо в кожної свій код.

Якщо уроків стане багато, зручніше назвати репозиторій `english` і зробити
всередині нього папки: `lesson5/`, `lesson6/` тощо.
